# Проверки скиллов: как запускать

Сохранённый набор проверок для пользовательских скиллов (карта скиллов — в README плагина). Нужен, чтобы после правки скилла или стандарта быстро перепроверить его, а не писать запросы заново.

## Что здесь лежит

| Файл | Что это |
| --- | --- |
| `queries.json` | 154 запроса: какой скилл должен сработать и какие не должны (в том числе «похожие, но не те»). |
| `queries-en.json` | английский набор для проверки английских формулировок. |
| `run_trigger.py` | Запускает запросы через `claude -p` и показывает, какие скиллы вызвались. Полностью закомментирован. |
| `make_fixtures.py` | Создаёт пробные проекты и файлы с намеренными изъянами (учебные, секреты поддельные). |
| [[Сценарии поведения]] | Описание проверок поведения скиллов на пробных данных: что запросить и что ожидать. |

## Проверка срабатывания

Запускай из папки `checks/` (или командой `/armarium:run-trigger-check`):

```
python3 -I run_trigger.py queries.json 4 results.json
```

Параметры: файл запросов, число параллельных запросов, файл результата; `--skill ИМЯ` — только запросы одного скилла; `--plugin-mode` — проверить рабочую копию плагина, а не установленный. В конце выводится, сколько запросов прошло. **Каждый запрос тратит токены аккаунта**, поэтому для одной правки лучше взять нужные запросы в отдельный файл, а не весь набор.

Нужна установленная командная строка `claude`. Срабатывание вероятностное: один запуск показывает явные ошибки, но не гарантию; спорные запросы стоит повторить несколько раз.

## Пробные данные для проверок поведения

```
python3 -I make_fixtures.py /путь/к/пустой/папке
```

Создаются шесть наборов (проекты на этапах 1 и 7, репозиторий устройства, бот с уязвимостями и «секретом» в истории git, бинарный файл с известной структурой, проект с зависимостью под GPL). Подробности в шапке скрипта.

Проверки поведения Claude запускает через субагентов — только с согласия пользователя, не больше 4 за раз, это тратит токены: ему даётся скилл, пробные данные и запрос из [[Сценарии поведения]], результат сравнивается с ожиданием. Хранилище при этом не меняется: заметки и файлы пишутся во временную папку.

## Когда прогонять

- после правки `SKILL.md`, шаблона или справки скилла: нужные запросы и сценарии;
- после правки стандарта: скилл `standards-audit` (проверка согласованности), потом срабатывание затронутых скиллов;
- после добавления нового скилла: запросы «должен» и «не должен» для него и для соседей (см. раздел «пересечения» в [[Сценарии поведения]]).

## Что известно о границах

- Срабатывание проверялось по одному запуску на запрос.
- Запросы писались автором скиллов, поэтому могут быть удобнее для описаний, чем реальные фразы; пополняй `queries.json` реальными формулировками, на которых скилл не сработал.
