# Игровой цикл и устройство движка

*Перенесено из справки `game-engines.md` скилла `code-coach` и дополнено 2026-11-04 по общим принципам; конкретные движки здесь не разбираются, их API проверяй в документации нужной версии.*

**Игровой цикл:** ввод → обновление состояния → отрисовка, по кругу. Главный вопрос — **шаг времени**:
- переменный шаг (`dt` = время прошлого кадра): просто, но физика и столкновения зависят от частоты кадров, повтор игры по записи ввода не воспроизводится;
- фиксированный шаг (обновление ровно N раз в секунду, отрисовка сколько успеет, накопитель времени): воспроизводимость и стабильная физика; между шагами отрисовка интерполирует состояние;
- «спираль смерти»: если шаг обновления дольше самого шага, накопитель растёт без конца; ограничивают число шагов за кадр.
Подробности интегрирования — `physics-coach`.

**Состояние отдельно от отрисовки:** логика игры не знает про окно и GPU; так проще тестировать, сохранять и повторять. Отрисовка читает состояние, но не меняет его.

**Организация объектов:**
- иерархия наследования («Враг → Летающий враг») — быстро начать, трудно сочетать свойства;
- компоненты на объекте (объект = набор компонентов) — гибко, как в большинстве движков;
- ECS (сущность = номер, компоненты = данные в массивах, системы = функции над наборами компонентов) — удобно для множества однотипных объектов и для кэша процессора, но сложнее в связях «один к одному» и в порядке систем.
Выбор — компромисс, решает пользователь; запись структур — `design-coach`.

**Граф сцены:** родитель-потомок для преобразований (колесо движется с машиной); не путать с хранением всех объектов.

**Ресурсы:** загрузка (синхронно при старте или в фоне), кэш по имени или идентификатору, подсчёт ссылок или явная выгрузка, горячая перезагрузка ассетов при разработке. Отдельный вопрос — что делать, если ассет не найден (заглушка, а не падение).

**Ввод:** опрос состояния клавиш против очереди событий; отображение «клавиша → действие» (переназначение, геймпад); ввод в фиксированном шаге — не терять нажатия между шагами.

**События и сообщения:** прямой вызов, очередь событий, наблюдатель; очередь развязывает системы, но усложняет порядок.

**Сохранения:** что сохраняется (состояние, а не объекты движка), версия формата сохранения и перенос старых, зерно генератора случайных чисел для воспроизводимости.

**Пошаговые игры и роглайки:** пошаговый цикл (ход игрока → ходы остальных), процедурная генерация уровней, зерно случайных чисел, интерфейс в терминале (`../../code-coach/references/tui.md`).

**Инструменты разработки:** отладочная отрисовка (рамки столкновений, пути), консоль команд, счётчик кадров и времени систем (профилирование — `debug-coach`).

**Где смотреть:** «Game Programming Patterns» (Роберт Нистром, доступна онлайн), «Game Engine Architecture» (Джейсон Грегори), статья «Fix Your Timestep!» (Гленн Фидлер, 2004) о фиксированном шаге; документация выбранного движка.

**Осторожно:** не строй движок «на все случаи»: начни с игры или демо, которая заставляет решать конкретные задачи (стандарт: `engine` проверяется на одной-двух демо-играх).

**Примеры на другой задаче:** минимальная игра (квадрат, «змейка», «понг»), не игра пользователя.
