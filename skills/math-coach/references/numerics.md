# Числа с плавающей точкой и численные методы

*Справка написана 2026-11-04. Стандарт — IEEE 754; поведение конкретного языка (оптимизации вроде `-ffast-math`, правила округления при выводе) — по документации языка и компилятора.*

**Как устроено:** знак, порядок, мантисса; `f32` — около 7 значащих десятичных цифр, `f64` — около 15–17. Шаг между соседними числами растёт с величиной числа: далеко от нуля точность хуже (большой мир в игре — «дрожание» дальних объектов; решение — начало координат рядом с камерой или `f64` для положений).

**Ловушки:**
- в `f64` 0,1 + 0,2 ≠ 0,3 (в `f32` случайно совпадает — проверено пересчётом): сравнение через допуск (абсолютный около нуля, относительный для больших чисел);
- потеря значимости при вычитании близких чисел (catastrophic cancellation);
- накопление ошибки в длинных суммах — сумма Кэхэна или парное суммирование;
- особые значения: ±0, ±∞, NaN (NaN не равен даже себе; распространяется по вычислениям); деление на ноль не паникует, а даёт ∞ или NaN;
- порядок операций меняет результат: сложение не ассоциативно, поэтому параллельные суммы дают разные числа;
- воспроизводимость между машинами и сборками (сетевые игры с детерминированным шагом) — не гарантирована без строгих правил; иногда берут фиксированную точку.

**Целые числа:** переполнение в Rust по умолчанию — паника в отладочной сборке и заворачивание в выпуске; управляется флагом `-C overflow-checks`, явно — методами `checked_`, `wrapping_`, `saturating_`, `overflowing_` (Rust Reference, «Operator expressions»). Деление на ноль паникует всегда. Для отрицательных `%` даёт остаток со знаком делимого (`-7 % 3` = −1, проверено запуском), евклидов остаток — `rem_euclid` и `div_euclid` (`(-7).rem_euclid(3)` = 2).

**Численные методы:**
- поиск корня: деление пополам (надёжно), Ньютон (быстро, нужна производная и хорошее начало);
- интегрирование функции: прямоугольники, трапеции, Симпсон;
- интегрирование движения (Эйлер, полуявный Эйлер, Верле, РК4) — `physics-coach`;
- устойчивость: метод может «взрываться» при большом шаге; признак — растущая энергия или колебания.

**Методы для симуляций и расчётов** (физическая постановка — `physics-coach`):
- порядок метода: локальная и глобальная ошибка; проверка порядка — уменьшить шаг вдвое и посмотреть, во сколько раз упала ошибка (≈ 2^p);
- устойчивость: область устойчивости метода, жёсткие системы (сильно разные масштабы времени) — неявные методы (неявный Эйлер, BDF), на каждом шаге решается система уравнений (Ньютон);
- симплектические методы (Верле, leapfrog) для гамильтоновых систем: при постоянном шаге ошибка энергии ограничена, а не растёт;
- большие системы K·x = f: разреженное хранение (CSR), прямые разреженные методы, итерационные (Якоби, Гаусс — Зейдель, сопряжённые градиенты для симметричных положительно определённых, GMRES для остальных), предобусловливание; критерий остановки по невязке;
- уравнения в частных производных: конечные разности, конечные объёмы, конечные элементы на уровне идеи (дискретизация пространства), условие Куранта для явных схем.
Источники: «Numerical Recipes» (идеи), «Solving Ordinary Differential Equations» — том I (Hairer, Nørsett, Wanner) и для жёстких систем том II (Hairer, Wanner, 2-е изд., 1996), Saad, «Iterative Methods for Sparse Linear Systems» (доступна онлайн).

**Интерполяция:** линейная lerp(a, b, t) = a + (b − a)·t; «гладкая ступенька» smoothstep; экспоненциальное сглаживание для независимости от частоты кадров: a + (b − a)·(1 − e^(−k·dt)).

**Где смотреть:** «What Every Computer Scientist Should Know About Floating-Point Arithmetic» (Goldberg, ACM Computing Surveys, 1991), «Numerical Recipes» (идеи; код там под своей лицензией).

**Пример на числах:** в `f32` 16 777 216 + 1 = 16 777 216: 2²⁴ ещё представимо точно, а 2²⁴ + 1 — первое целое, которое в `f32` не представимо.
