# Порядок работы в KiCad

Названия понятий верны; **пункты меню, команды и возможности проверяй в документации своей версии KiCad**.

**Порядок:**
1. **Схема (редактор схем).** Символы компонентов, соединения, имена цепей, позиционные обозначения; питание и земля через специальные символы. Проверка электрических правил (ERC): ловит несоединённые выводы, конфликты выводов, питание без источника.
2. **Назначение посадочных мест (footprints).** Каждому символу соответствует посадочное место из даташита производителя; проверка размеров по чертежу корпуса. Здесь чаще всего ошибаются, и ошибку находят после заказа.
3. **Плата (редактор плат).** Контур, крепёжные отверстия, расстановка компонентов (разъёмы и крепления согласуй с корпусом), правила проектирования (ширины дорожек, зазоры, размеры отверстий; значения по требованиям производства), трассировка, слои земли и питания. Проверка правил (DRC) ловит нарушения правил и неразведённые цепи.
4. **Подготовка к заказу.** Файлы для производства (Gerber, сверловка), список компонентов (BOM), файл расстановки, если заказывается сборка. Проверка перед заказом — скилл `hw-board-check`.

**Хорошие привычки:** проверять посадочные места по даташиту, а не доверять библиотеке; держать свою библиотеку компонентов (по стандарту это тип `lib`, имена `<вид>-<значение>-<корпус>`); обозначения и имена цепей по стандарту устройств; сохранять версию проекта в git с тегом на ревизию.

**Файлы проекта:** по стандарту лежат в `pcb/`, проект называется по коду устройства.

**Примеры на другом устройстве:** показывай приём (например, как найти ошибку ERC) на условной простой схеме.
