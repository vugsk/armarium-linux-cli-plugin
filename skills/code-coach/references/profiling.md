# Профилирование (где тормозит программа)

**Метод:** сначала измерить, потом менять. Не оптимизируй по догадке: узкое место обычно не там, где кажется. Порядок: задать цель (какое время или память считаются хорошими) → воспроизводимый замер → профиль (где тратится время или память) → одно изменение → повторный замер → сравнение.

**Что измерять:** время работы (общее и по частям), загрузка процессора, расход памяти и число выделений, ввод-вывод и сеть, для интерфейсов — время отклика и кадры.

**Инструменты** (названия существуют, **команды и флаги проверь в документации своей версии**):
- общие для Linux: `perf` (профиль по процессору), `time` для грубого замера, `strace` (системные вызовы), `valgrind` с инструментами `callgrind` и `massif` (вызовы и память, медленно);
- Rust: сборка `--release` обязательна для замеров; бенчмарки (встроенные и через сторонние крейты, например criterion); flamegraph-представления;
- C и C++: компиляция с отладочной информацией в релизном режиме, профилировщики `perf` и `gprof`;
- Python: модуль `cProfile`, `timeit` для малых замеров;
- Go: встроенный `pprof`;
- Java: инструменты JDK для профилирования (например, JFR);
- прошивки: счётчик циклов процессора или таймера, лишний вывод в UART сам искажает замер; логический анализатор для измерения по выводам.

**Осторожно:** отладочная сборка почти всегда медленнее релизной в разы; первый запуск показывает холодный кэш; замер на ноутбуке шумит от других процессов; микробенчмарки легко оптимизируются компилятором целиком.

**Примеры на другой задаче:** показывай приём (например, как прочитать «горячие» функции в профиле) на игрушечной программе, а не на коде пользователя.
