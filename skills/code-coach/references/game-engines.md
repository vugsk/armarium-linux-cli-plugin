# Игры и игровые движки

**Основа:** игровой цикл (ввод, обновление состояния, отрисовка), шаг времени (фиксированный или переменный, и почему это влияет на физику и воспроизводимость), отделение состояния игры от отрисовки.

**Темы движка:** управление ресурсами (загрузка, кэш, освобождение), графический конвейер и выбор графического API (проверь по его документации), ввод, звук, математика (векторы, матрицы, преобразования), столкновения и физика, граф сцены или компонентный подход (ECS), сериализация, инструменты разработки и отладка (отрисовка отладочной информации, профилирование).

**Роглайк и пошаговые игры:** пошаговый цикл, процедурная генерация уровней, зерно случайных чисел (воспроизводимость), сохранение и загрузка состояния, интерфейс (в терминале — см. `tui.md`).

**Где смотреть:** «Game Programming Patterns» (Роберт Нистром, доступна онлайн), «Game Engine Architecture» (Джейсон Грегори), документация выбранных графических и аудио-библиотек.

**Как вести проект** (по стандарту заметок): для `game` — заметки `Дизайн` и `Контент`, вертикальный срез на этапе 6 (одна играбельная петля), проверка играбельности и производительности; для `engine` — границы подсистем и проверка на одной-двух демо-играх; моды для чужих игр (`gmod`) см. `game-mods.md`.

**Осторожно:** не строй движок «на все случаи»: начни с игры или демо, которая заставляет решать конкретные задачи. Решения об архитектуре принимает пользователь.

**Примеры на другой задаче:** показывай приём на минимальной игре (например, движение квадрата по экрану), не на движке пользователя.
