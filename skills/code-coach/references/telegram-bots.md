# Telegram-боты

**Основа:** Bot API (HTTP-интерфейс, документация core.telegram.org/bots/api). Бот создаётся через BotFather и получает токен: **это секрет**, он не попадает в репозиторий, журналы и сообщения об ошибках (`.env` и переменные окружения, рядом `.env.example` без значений).

**Получение событий:** два способа: опрос сервера (long polling) и вебхук. Опрос проще: не нужен публичный адрес. Вебхук требует публичного адреса с HTTPS и защиты (проверка секретного токена вебхука, если используется). Что именно поддерживается и какие лимиты действуют сейчас, проверяй по документации Bot API, а не по памяти.

**Темы:** типы обновлений (сообщения, нажатия кнопок, встроенный режим), команды, клавиатуры и кнопки, хранение состояния диалога (в памяти или в хранилище), ограничения частоты запросов, ошибки сети и повторные попытки, обработка нескольких пользователей одновременно.

**Библиотеки** (существуют; проверяй актуальность): Python — python-telegram-bot, aiogram; Rust — teloxide; для клиентов пользователя (не бота) существует отдельная библиотека TDLib. Выбор библиотеки решает пользователь.

**Безопасность:** не доверяй входящему тексту (проверка и экранирование), ограничь, кто может вызывать административные команды, не логируй токен, храни зависимости обновлёнными.

**Уведомления из GitHub и подобные проекты:** подумай, откуда приходят события (вебхуки GitHub или опрос API) и как проверяется их подлинность; конкретные способы проверь в документации источника.

**Примеры на другой задаче:** показывай приём (например, обработку команды) на минимальном эхо-боте, не на боте пользователя.
