# Текстовые интерфейсы (TUI)

**Как устроен терминал:** программа пишет в терминал текст и управляющие последовательности (escape-последовательности, стандарт ECMA-48), терминал рисует; описание возможностей терминалов — terminfo. Обычный режим терминала строковый (cooked): ввод приходит построчно; для TUI включают «сырой» режим (raw), где клавиши приходят сразу. Для полноэкранного интерфейса используют альтернативный экран, чтобы после выхода терминал вернулся в прежнее состояние.

**Темы:** цикл событий (ввод, обновление состояния, отрисовка), перерисовка только изменившегося, обработка клавиш и мыши, изменение размера окна (сигнал SIGWINCH), ширина символов Юникода (широкие символы и составные знаки ломают раскладку), поддержка цветов, ограничения разных терминалов.

**Главное правило:** при выходе, в том числе при панике или ошибке, **всегда восстанавливай терминал** (выключи сырой режим, вернись с альтернативного экрана). Иначе пользователь остаётся с «сломанной» консолью.

**Библиотеки** (существуют; проверяй актуальность и версию): Rust — ratatui с crossterm; C и C++ — ncurses; Go — bubbletea; Python — curses или textual.

**Проверка:** TUI удобно проверять вручную и снимками экрана; автоматизировать можно запуском в псевдотерминале или оболочке вроде tmux. Планирование проверок — скилл `test-plan`.

**Архитектура:** отделяй состояние и логику от отрисовки: тогда логику можно проверять без терминала.

**Примеры на другой задаче:** показывай приём на минимальном интерфейсе (например, список с выбором строки), не на интерфейсе пользователя.
