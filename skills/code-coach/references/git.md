# Git

**Здесь режим другой:** git — инструмент, а не код проекта, поэтому **команды можно давать прямо**: объясни, что происходит, и назови нужную команду. Пользователь выполняет её сам, ты в его репозитории git-команды не запускаешь, если он об этом не просил.

**Темы:** коммиты и история, ветки, слияние и перебазирование (merge и rebase), конфликты, отмена изменений (restore, reset, revert), stash, reflog (история перемещений указателей, спасает после ошибки), теги, удалённые репозитории (remote, fetch, pull, push), `.gitignore`, подмодули.

**Где смотреть:** `git help <команда>` и книга Pro Git (git-scm.com/book). Для подробностей конкретной версии git проверяй документацию, а не память.

**Опасные команды — предупреждай и объясняй последствия до того, как назвать:**
- `git reset --hard`: стирает несохранённые изменения в рабочих файлах.
- `git push --force`: перезаписывает историю на сервере; безопаснее `--force-with-lease`, которая не затрёт чужие коммиты.
- `git clean -fd`: удаляет неотслеживаемые файлы без корзины.
- `git branch -D`: удаляет ветку, даже если её коммиты не слиты (вернуть можно через reflog, пока он не очищен).
- Перебазирование и правка уже опубликованных коммитов: ломает историю тем, кто её уже скачал.

**Как выбирать «откат»:** `git restore` возвращает файлы, `git revert` создаёт новый коммит-отмену и безопасен для опубликованной истории, `git reset` двигает ветку и меняет историю. Объясни разницу, прежде чем рекомендовать.

**Связь со стандартами пользователя:** ветки поколений `gen-N`, теги `g<N>-v…`, коммиты по Conventional Commits — см. скилл `release-versioning`.
