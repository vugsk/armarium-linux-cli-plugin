# Плагины к программам

*Справка написана 2026-10-24 по общим принципам; конкретные программы-хозяева в ней не разбираются, их интерфейс плагинов проверяй в документации.*

**Устройство:** программа-хозяин определяет интерфейс плагина (описание, точка входа, доступные возможности), а плагин подгружается хозяином. Модели бывают разные: плагин в одном процессе с хозяином (динамическая библиотека или скрипт) или отдельным процессом, который общается с хозяином сообщениями. **Какая модель у конкретной программы, проверяй в её документации**, не называй имена функций и форматы по памяти.

**Версии интерфейса:** хозяин меняет интерфейс плагинов, старые плагины ломаются. Фиксируй, для какой версии написан плагин.

**Права и изоляция:** плагин в одном процессе работает с правами хозяина и может его уронить; отдельный процесс безопаснее, но сложнее по обмену данными. Запрашивай минимум возможностей.

**Распространение:** у многих программ есть каталог плагинов со своими правилами; условия смотри на страницах для разработчиков.

**Не путать с другими типами:** для браузера есть `ext` (см. `browser-ext.md`), для игр отдельный `gmod` (см. `game-mods.md`).

**Связь со стандартами:** `plugin` относится к группе «ПО», особенностей этапов нет (решено 2026-10-24, группа предложена мной). Имя репозитория по стандарту названий: `<проект>-<платформа>-<ui>-plugin`.

**Примеры на другой задаче:** показывай приём (например, регистрацию команды в хозяине) на минимальном плагине для другой программы, не на плагине пользователя.
