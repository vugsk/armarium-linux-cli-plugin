# Конвейер отрисовки

*Справка написана 2026-11-04 по общим принципам; подробности стадий конкретного API — по его спецификации.*

**Растеризация по шагам:** вершины (позиции и атрибуты в буфере) → вершинный шейдер (переводит в пространство отсечения) → сборка примитивов → отсечение и деление на `w` → преобразование в окно → растеризация (какие пиксели покрывает треугольник) → фрагментный шейдер (цвет каждого фрагмента) → проверки глубины и трафарета (логически после фрагментного шейдера; GPU может делать их раньше — ранние тесты) → смешивание → кадровый буфер.

**Пространства координат:** модель (локальные) → мир (матрица модели) → вид или камера (матрица вида) → отсечение (матрица проекции) → нормализованные координаты устройства → окно. Путаница с порядком умножения и с тем, в каком пространстве считается освещение, — главная причина «ничего не видно». Соглашения различаются: направление оси Y, диапазон глубины (0..1 или −1..1), правая или левая система — смотри документацию API. Сами матрицы — `math-coach`.

**Проекции:** перспективная (поле зрения, ближняя и дальняя плоскость; точность глубины падает с отношением дальней к ближней, помогает обратная глубина) и ортографическая (2D, чертежи, тени от направленного света).

**Данные на GPU:**
- вершинный и индексный буфер, формат вершин (атрибуты, смещения, шаг);
- константы и uniform-буферы для данных кадра и объекта; правила выравнивания — по спецификации;
- текстуры и сэмплеры (фильтрация, мип-уровни, адресация на краях); цветовое пространство: sRGB-текстура для цвета, линейная для нормалей и масок;
- кадровые буферы и вложения (цвет, глубина), отрисовка в текстуру.

**Глубина и прозрачность:** непрозрачное — с тестом и записью глубины, в любом порядке (лучше спереди назад); прозрачное — после, сзади наперёд, без записи глубины; порядок прозрачного — источник артефактов, есть приёмы без сортировки (order-independent transparency).

**Отсечение лишнего:** отсечение по пирамиде видимости на CPU, удаление задних граней, уровни детализации.

**Вызовы отрисовки:** каждый вызов и смена состояния стоят времени CPU и драйвера; группировка по материалу, инстансинг для множества одинаковых объектов.

**Трассировка лучей** — другой подход (луч из камеры ищет пересечения); аппаратная: в Vulkan — через расширения KHR, в Direct3D 12 (DXR) и Metal — в самом API при поддержке устройства (по сведениям сверки, первоисточники не открывались — проверь по документации).

**Где смотреть:** «Real-Time Rendering» (Akenine-Möller и др., 4-е изд., 2018), learnopengl.com (идеи переносятся на другие API), документация выбранного API.

**Примеры на другой задаче:** цветной треугольник, куб с текстурой.
