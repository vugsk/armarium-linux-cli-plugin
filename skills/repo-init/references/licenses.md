# Лицензии: справка для выбора

Общая справка, **не юридическая консультация**. Сверена 2026-10-24 с официальными источниками: SPDX, opensource.org, choosealicense.com, apache.org, gnu.org (GPL FAQ и список лицензий GNU), creativecommons.org (CC0, FAQ), tapr.org, тексты CERN-OHL, документация Cargo. FAQ Creative Commons, список лицензий GNU, GPL FAQ и тексты LGPL и AGPL прочитаны целиком. **Не проверено:** совместимость LGPL-библиотеки конкретно с MIT и Apache-2.0 материалы GNU напрямую не описывают (опирайся на §4 LGPL и текст лицензии); отдельный FAQ по CC0 не читался. Условия всегда проверяй по тексту лицензии (spdx.org/licenses, choosealicense.com); при сомнении так и скажи пользователю.

## Лицензии для программ

| Лицензия | Суть | Когда подходит |
| --- | --- | --- |
| MIT | очень короткая, разрешительная: можно использовать, менять, распространять, в том числе в закрытых проектах; нужно сохранить уведомление об авторстве и текст лицензии; явной патентной оговорки нет. В списке GNU называется Expat (GNU считает название «MIT» неоднозначным) | небольшие проекты, максимум простоты и свободы |
| BSD-2-Clause, BSD-3-Clause | по духу как MIT: сохранить уведомление в исходниках, а в бинарных сборках воспроизвести его в документации, отказ от гарантий; в 3-Clause запрещено использовать имена правообладателя и участников для одобрения или продвижения производных продуктов без письменного разрешения | то же, что MIT |
| Apache-2.0 | разрешительная; явная патентная лицензия от контрибьюторов (§3), которая прекращается, если пользователь подаёт патентный иск; изменённые файлы нужно отмечать (§4) | когда важна патентная ясность |
| MPL-2.0 | слабый копилефт на уровне файлов: файлы с кодом под MPL (в том числе изменённые) остаются под MPL и распространяются с исходниками; новые файлы в составе более крупного произведения могут быть под другими условиями, в том числе закрытыми; есть явная патентная лицензия | библиотека, изменения которой хочется получать обратно |
| LGPL-3.0 | слабый копилефт для библиотек: закрытая программа может использовать библиотеку на своих условиях, если они не запрещают модификацию библиотеки и обратную разработку для отладки модификаций; плюс условия §4: заметное уведомление об использовании библиотеки, копии лицензий, либо подходящий механизм общей (shared) библиотеки (библиотека берётся с компьютера пользователя и работает с изменённой совместимой версией, §4d1), либо передача Corresponding Application Code в виде, позволяющем перелинковать программу с изменённой библиотекой (§4d0), и Installation Information там, где она требуется. Проверь по §4 | библиотека, которую будут подключать в том числе закрытые программы |
| GPL-3.0 | сильный копилефт: производная работа при распространении лицензируется целиком под GPL с исходниками (§5(c)) | чтобы все производные оставались открытыми |
| AGPL-3.0 | как GPL-3.0, плюс §13: если вы **изменили** программу и ваша версия поддерживает удалённое взаимодействие по сети, нужно предложить всем таким пользователям им исходники изменённой версии | сетевые сервисы, которые нужно сохранить открытыми |
| Unlicense | посвящение произведения в общественное достояние (в юрисдикциях, где есть авторское право); по списку GNU совместима с GPL | когда права не нужны |
| CC0-1.0 | отказ от авторских и смежных прав в пользу общественного достояния (§2); **патентные права и товарные знаки не затрагиваются, патентной лицензии нет** (§4(a)). Резервная лицензия (§3), если отказ признан недействительным: безвозмездная, неисключительная, безотзывная, безусловная, непередаваемая, без права сублицензирования, только на авторские и смежные права, патентов не касается. FAQ Creative Commons называет CC0 допустимой для программ, список GNU считает её совместимой с GPL, но не рекомендует для ПО именно из-за отсутствия патентной лицензии | когда права не нужны, а патентные вопросы вас не касаются |

## Лицензии для железа и данных

- **Железо (схемы, платы):** лицензии для программ созданы для кода. Для аппаратуры есть специальные лицензии. CERN называет их «reciprocal» (взаимными), а не «copyleft»; в программном мире по смыслу близки к копилефту, но это сравнение не слова CERN.
  - **CERN-OHL-P-2.0** (Permissive): производную можно распространять на других условиях, если сохранены уведомления, добавлено уведомление об изменении с датой и кратким описанием и приложена копия лицензии (§3.1, 3.3, 3.4); для продуктов достаточно дать получателю доступ к уведомлениям, публиковать исходники не требуется (§4).
  - **CERN-OHL-W-2.0** (Weakly Reciprocal): изменённый Covered Source остаётся под W целиком, кроме Available Components и External Material (то, что подключено через документированный интерфейс, описанный в Covered Source): они остаются под своими лицензиями (§3.3(d), §4.2). При передаче продукта нужно дать Complete Source или сообщить, где он находится (Source Location, доступно не менее трёх лет по разумному ожиданию лицензиара).
  - **CERN-OHL-S-2.0** (Strongly Reciprocal): включение в более крупную работу считается модификацией, и вся такая работа лицензируется под S, исключены только Available Components (в S это физические части); понятия External Material в S нет (§3.2, 3.3(d)). Условия публикации исходников те же, что у W.
  - Вариант (P, W или S) нужно указать в уведомлении, иначе по умолчанию действует S. Лицензию разрешено использовать только без изменения текста. В CERN-OHL есть патентная лицензия, прекращающаяся при патентном споре о Covered Source.
  - **TAPR-OHL-1.0:** по описанию TAPR это рамка для аппаратных проектов, не в первую очередь лицензия на авторское право; **не охватывает** программы, прошивку и код в программируемых устройствах.
- **Документация, изображения, текстовые и «эстетические» материалы:** Creative Commons подходит: CC BY 4.0 (CC-BY-4.0, с указанием авторства) или CC BY-SA 4.0 (CC-BY-SA-4.0, производные под той же или совместимой лицензией). FAQ Creative Commons называет единственными исключениями программы и hardware: CC **не рекомендует свои лицензии для программ и аппаратуры** (для программ допустима CC0; про аппаратуру в FAQ только эта фраза). Для программ причины названы такие: в CC-лицензиях нет условий про исходный код и патенты, и они несовместимы с основными лицензиями ПО. Корпуса, 3D-модели и схемы FAQ не разбирает: различие «материал и проект изделия» — вывод справки, а не FAQ, решает пользователь; для схем и плат используй лицензии из списка выше. Прочие условия CC: лицензия безотзывна; патенты и товарные знаки CC-лицензии не лицензируют (логотип и название проекта под CC FAQ класть не рекомендует); ShareAlike действует при изменении работы и публичной раздаче; «совместимой» считается лицензия, официально признанная CC (BY-SA 4.0 односторонне совместима с GPLv3 для содержимого, встроенного в программный код).
- **Прошивка устройства** — программа. По FAQ CERN прошивка это ПО, она лицензируется отдельно лицензиями для программ (CERN рекомендует для ПО, например, GPL-3.0-or-later, LGPL-3.0, MPL-2.0 или Apache-2.0), а понятие Available Components к ней не применяется; для HDL и FPGA («gateware») CERN-OHL подходит напрямую. Лицензия TAPR OHL прошивку прямо исключает.

## Совместимость с лицензиями библиотек (общие правила, проверяй на конкретном случае)

- **GPL-библиотека.** По GPL FAQ связывание GPL-работы с другими модулями, статическое или динамическое, создаёт комбинированную работу, и условия GPL распространяются на всю комбинацию (#GPLStaticVsDynamic, #IfLibraryIsGPL). Отдельные модули могут оставаться под своими GPL-совместимыми лицензиями (например, Expat), но работа в целом распространяется на условиях GPL. Лицензия MIT на весь результат не сохраняется.
- **Aggregate.** GPL разрешает распространять независимые программы на одном носителе, даже под несвободными лицензиями; нельзя лишь выпускать агрегат под лицензией, запрещающей пользователям права по лицензиям отдельных программ (#MereAggregation). Граница между двумя программами и одной программой из двух частей — юридический вопрос, который решают суды; для плагинов FAQ даёт ориентиры (#GPLPlugins): общие функции и структуры данных означают единую программу, обмен через fork/exec без тесной связи — отдельные программы.
- **Совместимость с GPL по списку GNU:** MIT (Expat), 2-clause BSD (FreeBSD License), 3-clause BSD (Modified BSD), Apache-2.0 (только с GPLv3, **не с GPLv2** из-за условий о прекращении патентной лицензии и возмещении убытков), Unlicense и CC0 совместимы с GPL. MPL-2.0 косвенно совместима с GPL 2.0, LGPL 2.1, AGPL 3 и более поздними версиями через §3.3 при условии, что файлы под MPL остаются доступны и под MPL; если в уведомлении стоит «Incompatible With Secondary Licenses», такой код с GPL и AGPL несовместим. Проверяй уведомления в каждой библиотеке.
- Код под Apache-2.0 можно включать в проект под GPL-3.0, а код под GPL-3.0 в проект под Apache-2.0 включать нельзя (apache.org).
- **LGPL:** по GPL FAQ (#LGPLStaticVsDynamic): при статическом подключении нужно предоставить программу в объектном (не обязательно исходном) виде, чтобы пользователь мог изменить библиотеку и пересобрать; при динамическом подключении к библиотеке, уже установленной у пользователя, исходники библиотеки передавать не нужно; подробности в LGPL-3.0 §4. LGPL-3.0 совместима с GPL-3.0 (итог под GPL-3.0) и несовместима с GPLv2-only (FAQ #AllCompatibility, список GNU). Код под другой лицензией, в том числе разрешительной, может использовать LGPL-библиотеку на условиях §4; для конкретной пары (например, MIT или Apache-2.0) GNU это отдельно не описывает, сверяй с текстами. **MPL:** решает не способ подключения, а то, какие файлы содержат код под MPL.
- **AGPL:** обязанность по исходникам возникает при изменении программы и работе с ней по сети, если версия поддерживает такое взаимодействие (§13). AGPL-3.0 и GPL-3.0 можно объединять в одном проекте, каждая часть остаётся под своей лицензией, но переводить код одной в другую нельзя; с GPLv2-only AGPL несовместима (§13, список GNU, FAQ #AGPLGPL).
- Лицензию библиотеки не удалось определить: это **«не проверено»**, а не «подходит».

## Как проверять зависимости

1. Найди зависимости проекта: манифесты и lock-файлы (`Cargo.toml`/`Cargo.lock`, `requirements.txt`/`pyproject.toml`, `go.mod`/`go.sum`, `pom.xml`/`build.gradle`, подключения в `CMakeLists.txt`, библиотеки, положенные в репозиторий). Транзитивные зависимости тоже.
2. Для каждой возьми лицензию **из источника**, не по памяти: поле license в манифесте или реестре пакетов (crates.io, PyPI, pkg.go.dev, Maven Central) либо файл LICENSE в репозитории библиотеки. Для Rust `cargo metadata` выводит у пакетов поля `license` и `license_file`; если оба `null`, лицензия не определена («не проверено»). Проверь на своей версии.
3. Составь таблицу: зависимость · версия · лицензия и откуда взята · совместимость с выбранной лицензией · комментарий. Итог: что конфликтует, что не проверено.
4. Конфликты покажи до выбора, а не после.
