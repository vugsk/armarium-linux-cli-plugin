# Именование проектов и устройств

Источник истины — два файла в хранилище Obsidian. Словари в них меняются (новые значения сначала добавляются в файл, потом используются), поэтому не пересказывай их по памяти — читай нужный файл целиком, он короткий.

- ПО: `/home/germanf0x/Documents/disk_docs/Book/Проекты/Стандарт по названию проектов.md`
- Устройства (платы, корпуса, свои компьютеры и процессоры): `/home/germanf0x/Documents/disk_docs/Book/Проекты/Стандарт по названию устройств.md`

## Порядок работы

1. **Что именуется — ПО или устройство?** Устройство с прошивкой даёт два имени: репозиторий устройства (`<код>-<основа>-dev`) и отдельный репозиторий прошивки по стандарту ПО (`<код>-embed-headless-fw`) с тем же кодовым словом. Если из запроса не ясно, что именно, спроси.
2. **Прочитай нужный файл.** Ориентир по схемам (детали, словари и фильтры — только из файла):
   - ПО: `<проект>-<платформа>-<ui>-<тип>`
   - устройство: `<код>-<основа>-<вид>`
   - публичное имя: `<АББРЕВИАТУРА>-<поколение>` (кириллица + латинский транслит + расшифровка по буквам)
   - ветка поколения `gen-N`; теги ПО `g<N>-v<версия>`, теги устройства `g<N>-<часть>-<ревизия>`
3. **Предложи 2–3 варианта кодового слова.** Для каждого скажи способ (сжатие сути, склейка, тематический пул, слово на другом языке), что подставлено в каждый блок имени и почему. Прогони через фильтры из файла: регистр, длина, без дефисов и цифр, произносимость, не совпадает со значениями словарей.
4. **Проверь уникальность** по таблице соответствий в том же файле. Проверку «не занято на GitHub и в менеджере пакетов» предложи сделать пользователю или выполни поиском, если он разрешил.
5. **Публичное имя** предлагай только если об этом спросили или проект идёт к `1.0.0` — оно придумывается один раз перед релизом.

## Границы

Пользователь не любит, когда за него закрывают решения: имя — это предложение, пока он явно не выбрал. Поэтому:

- Не вписывай имя в таблицу соответствий и не создавай репозитории или ветки, пока он не подтвердил выбор.
- Если нужного значения нет в словаре, не придумывай его молча. Скажи, что значение новое, предложи его и добавляй в файл стандарта только после подтверждения.
- Свои предложения помечай явно («это моё предложение, вы о нём не просили»).
- Техническое имя не переименовывается никогда — если пользователь хочет «переименовать», объясни, что для этого есть публичное имя.
- Если стандарт и пожелание пользователя расходятся, не подгоняй ответ: покажи расхождение и спроси, менять ли стандарт.
