# Свой физический движок: архитектура и порядок разработки

*Справка написана 2026-11-04 по общим принципам и устройству открытых движков (Box2D, Bullet, Jolt, Rapier — как учебный материал; их устройство и лицензии проверяй по репозиториям нужной версии). Порядок этапов — моё предложение; решает пользователь.*

**Сначала рамки** (раундом `AskUserQuestion`): 2D или 3D; для игр (устойчивость и скорость важнее точности) или для расчётов (точность и сходимость — см. `scientific-sim.md`); нужен ли детерминизм; язык; библиотека для других или часть своего движка. Физический движок для других — тип `lib` по стандарту (заметка `Публичный интерфейс` на этапе 3, политика версий); часть игрового движка — подсистема `engine` (границы подсистем в `Архитектуре`).

**Части движка:**
- **мир** — владеет всем, делает шаг, хранит настройки (гравитация, число итераций);
- **тела** — масса, инерция, положение, ориентация, скорости, тип (динамическое, кинематическое, статическое); снаружи — по дескриптору (handle), не по указателю;
- **формы (коллайдеры)** — геометрия столкновений, привязанная к телу со смещением; материал (трение, упругость), фильтры;
- **широкая фаза** — пары кандидатов (динамическое BVH с расширенными AABB, sweep and prune, сетка);
- **узкая фаза** — пары форм → контактные многообразия;
- **менеджер контактов** — контакты живут между кадрами (появился, длится, исчез), события для пользователя;
- **соединения (joints)** — ограничения между телами;
- **острова** — связные группы тел и ограничений, решаются и засыпают вместе;
- **решатель** — импульсы для контактов и соединений;
- **запросы** — луч, пересечение формы, ближайшая точка, без шага мира;
- **отладочная отрисовка** — интерфейс, который движок вызывает, а рисует пользователь движка.

**Типичный порядок одного шага** (у разных движков отличается — сверяй с исходниками того, что изучаешь): силы → скорости → обновление широкой фазы → узкая фаза и контакты → построение островов → решение ограничений по скоростям (несколько итераций) → интегрирование положений → коррекция положений → засыпание → события.

**Порядок разработки и проверка каждого этапа:**

| Этап | Что сделать | Готово, когда |
| --- | --- | --- |
| 1 | частица, гравитация, фиксированный шаг (`integration.md`) | свободное падение совпадает с аналитикой с ожидаемой ошибкой; при уменьшении шага ошибка падает |
| 2 | твёрдое тело без столкновений: ориентация, инерция, моменты | свободное вращение не набирает энергию сверх ожидаемого; момент импульса сохраняется, если учтён гироскопический член (без него сохраняется угловая скорость) |
| 3 | узкая фаза для простых пар: сфера–сфера, сфера–плоскость, бокс–бокс (SAT) | тесты на пары с известным ответом, включая касание и вырожденные случаи |
| 4 | контакты и решатель: импульс по нормали, трение, накопление импульсов (`constraints-deep.md`) | шар отскакивает с заданной упругостью; ящик лежит на полу без дрожания |
| 5 | контактное многообразие, кэш контактов, тёплый старт | стопка из 5–10 ящиков стоит заданное время; пирамида не расползается |
| 6 | широкая фаза | те же пары, что и при полном переборе n², на сцене из сотен тел; время шага измерено |
| 7 | соединения: расстояние, шарнир, ползун, пределы, моторы | маятник и цепочка ведут себя по аналитике или эталонному движку |
| 8 | выпуклые формы (GJK, EPA), составные формы, сетки для статики | тесты на пары; нет «залипания» на краях треугольников |
| 9 | непрерывное столкновение (CCD) | пуля не проходит сквозь тонкую стену при любом шаге из заданного диапазона |
| 10 | острова и засыпание | покоящаяся сцена не тратит время; разбуженное тело будит соседей |
| 11 | производительность и потоки | профиль шага, параллельный решатель даёт тот же результат (если нужен детерминизм) |
| 12 | публичный интерфейс, запросы, события, документация | демо-сцены пользователя движка работают без знания внутренностей |

**Эталонные сцены** для проверки на каждом этапе: падение, отскок, наклонная плоскость с трением (скатывается или нет при известном угле), стопка, пирамида, домино, маятник и двойной маятник, цепочка, быстрый снаряд и тонкая стена, тело на вращающейся платформе. Запись траекторий и энергии в файл и сравнение между версиями движка — регрессионные тесты (пишет `test-plan`).

**Осторожно:** не делай всё сразу «как в больших движках»: каждый этап должен работать и проверяться до следующего. Решения о составе и порядке принимает пользователь, записываются в `Решения` и `План` (`plan-breakdown`).
