# Низкий уровень игрового движка

*Справка написана 2026-11-04 по общим принципам. Игровая часть движка (цикл, сцена, ECS, ресурсы) — `game-dev-coach`, рендер — `graphics-coach`. API окон, ввода и потоков — по документации платформы или библиотеки.*

**Платформенный слой:** окно, ввод, время, файлы, потоки, загрузка библиотек — за одним интерфейсом, остальной движок про платформу не знает. Готовые библиотеки окна и ввода или свой слой поверх API ОС (X11 или Wayland, Win32) — выбор пользователя; кандидатов проверяет `dependency-audit`.

**Память в движке:**
- кадровый (линейный) аллокатор для временных данных кадра — сбрасывается целиком;
- пулы для объектов одного типа, индексы с поколением (generational index) вместо указателей, чтобы ловить обращения к удалённым объектам;
- расположение данных: массив структур против структуры массивов, плотные массивы для кэша процессора;
- бюджеты памяти по подсистемам и счётчики для отладки.
Подробно об аллокаторах — `low-level-libs.md`.

**Потоки и задачи:**
- поток на подсистему (рендер, звук, загрузка) — просто, но плохо масштабируется;
- пул потоков и система задач (job system) с графом зависимостей — работы кадра делятся на мелкие задачи;
- синхронизация: двойная буферизация состояния между логикой и рендером, очереди без блокировок только при явной необходимости (сложно проверить);
- поток звука — с жёсткими сроками: в нём не выделяют память и не ждут блокировок.

**Горячая перезагрузка кода:** игровая логика в динамической библиотеке, движок перезагружает её без перезапуска; состояние хранится на стороне движка, ABI между ними — простой (в Rust — `extern "C"` и `#[repr(C)]`, ограничения — по Reference и Nomicon); паника, вышедшая через `extern "C"`, аварийно завершает процесс, для раскрутки стека нужен `extern "C-unwind"`.

**Профилирование и инструменты:** метки зон кадра, счётчики времени систем, сбор в профилировщик (`debug-coach`, справка `../../code-coach/references/profiling.md`).

**Сборка и платформы:** кросс-компиляция и CI — `ci-coach`.

**Где смотреть:** «Game Engine Architecture» (Джейсон Грегори: глава о параллелизме, разделы об управлении памятью), документация платформы и выбранных библиотек.

**Примеры на другой задаче:** пул задач, складывающий числа в массиве; аллокатор кадра для строк отладочного текста — не движок пользователя.
