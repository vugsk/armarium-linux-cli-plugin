# Низкоуровневые библиотеки: память, файловые системы, сеть, хранилища

*Справка написана 2026-11-04 по общим принципам. Форматы дисков, системные вызовы и протоколы — только по спецификации, `man` и RFC, не по памяти.*

**Аллокаторы:**
- линейный (bump): выделение сдвигом указателя, освобождение всего сразу — для кадра или запроса;
- пул (блоки одного размера, список свободных): быстро и без фрагментации для однотипных объектов;
- стековый, свободный список с разными размерами, buddy, slab — у каждого свой компромисс скорости, фрагментации и простоты;
- обязательны выравнивание, учёт размера при освобождении, поведение при нехватке памяти; ошибки ловят санитайзеры и Miri (`debug-coach`);
- в Rust в стабильной версии есть только `unsafe trait GlobalAlloc` с атрибутом `#[global_allocator]` (один аллокатор на программу); трейт `Allocator` и коллекции со своим аллокатором (`Vec::new_in`) — только nightly (`#![feature(allocator_api)]`, проверено по документации `std` 1.96); статус проверь в документации нужной версии.

**Файловые системы:** блоки и суперблок, индексные узлы (inode) и каталоги как файлы особого вида, битовые карты свободного места; надёжность при сбое питания — журнал или копирование при записи; кэш страниц. Начинать удобно с образа диска в файле и монтирования через FUSE (своя ФС как обычная программа) — прежде чем в ядре.

**Сетевой стек:** уровни (канальный, IP, TCP/UDP), буферы, конечный автомат TCP, контрольные суммы, порядок байт. Для учёбы — устройство TUN/TAP в Linux, чтобы получать сырые пакеты в своей программе (TUN — IP-пакеты, TAP — кадры Ethernet). Поведение протоколов — по RFC (номер и раздел).

**Хранилища и базы данных:**
- журнал с дозаписью (append-only log) — самое простое надёжное хранилище;
- B-дерево (страницы на диске, хорошо для чтения и диапазонов) против LSM-дерева (дозапись и слияние, хорошо для записи);
- журнал предзаписи (WAL) и `fsync` для надёжности; после создания или переименования файла `fsync` нужен и для каталога (`man 2 fsync`); что гарантирует `fsync` на конкретной ФС — по документации;
- транзакции, изоляция, восстановление после сбоя — проверять тестами с «выключением посередине».

**Общее для библиотек:** публичный интерфейс отдельно от внутренностей (стандарт: заметка `Публичный интерфейс` для `lib`), явные ошибки вместо паник, документированные условия `unsafe`, тесты на граничные случаи и на сбои.

**Где смотреть:** «Operating Systems: Three Easy Pieces» (главы о памяти в части Virtualization и часть Persistence), «Database Internals» (Алекс Петров), «Designing Data-Intensive Applications» (2-е изд., 2026: Martin Kleppmann, Chris Riccomini — по сведениям сверки, сам я не проверял), `man` нужных системных вызовов, RFC протоколов.

**Примеры на другой задаче:** аллокатор на статическом массиве, ФС в файле на 64 блока, хранилище «ключ — значение» с дозаписью — не библиотека пользователя.
