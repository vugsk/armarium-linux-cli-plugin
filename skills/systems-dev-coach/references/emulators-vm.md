# Эмуляторы процессоров и виртуальные машины

*Справка написана 2026-11-04 по общим принципам. Коды команд, флаги, тайминги и карты памяти конкретных процессоров и консолей — только по их документации или руководству архитектуры, не по памяти.*

**Основной цикл:** выборка команды по счётчику команд → декодирование → выполнение (изменить регистры, память, флаги) → учёт тактов → обработка прерываний. Состояние процессора — структура с регистрами, флагами и счётчиком тактов; память — отдельная шина с картой адресов (ОЗУ, ПЗУ, порты устройств).

**Шина и устройства:** чтение по адресу может попасть в устройство (таймер, видео, звук), а не в память; запись в регистр устройства меняет его состояние. Карта адресов — из документации машины.

**Точность:**
- по командам (команда выполняется целиком) — проще, хватает для многих программ;
- по тактам (устройства продвигаются синхронно с процессором) — нужна, если программы зависят от точного времени;
- уровень выбирает пользователь; от него зависит устройство всего эмулятора.

**Проверка:** тестовые программы и наборы тестов для архитектуры (у многих архитектур есть открытые тестовые ROM и журналы эталонного выполнения), сравнение журнала «команда — регистры» с эталоном, пошаговый отладчик эмулятора.

**Виртуальная машина своего языка:**
- стековая (операнды на стеке, короткий байт-код) против регистровой (меньше команд, сложнее компилятор);
- формат байт-кода: код операции и операнды, таблица констант, информация для отладки (номера строк);
- цикл интерпретации: `switch` по коду операции или шитая диспетчеризация (переход сразу к обработчику следующей команды); в C её делают через computed goto — расширение GCC и Clang «labels as values», в стандарте C его нет;
- память: стек вызовов, кадры, куча, сборщик мусора (см. `lang-dev.md`).

**JIT:** перевод горячих участков в машинный код во время работы; требует знания кодировки команд целевой архитектуры, страниц памяти с правом исполнения (и запрета одновременной записи и исполнения в некоторых ОС), на ARM — синхронизации кэшей после записи кода (очистка кэша данных и сброс кэша команд с барьерами; в C — `__builtin___clear_cache`; точная последовательность — по руководству Arm). Большой шаг — только после работающего интерпретатора.

**Правовое:** эмулятор своего устройства или открытой архитектуры — без вопросов; образы ПЗУ и BIOS чужих машин защищены авторским правом, их пользователь берёт только со своего устройства или из законного источника. Разбор чужого ПЗУ — `reverse-engineering`.

**Где смотреть:** руководство архитектуры (например, спецификация RISC-V — открытая, удобна для учёбы), «Crafting Interpreters» (часть про байт-код), документация выбранной платформы.

**Примеры на другой задаче:** выдуманный процессор из 4–8 команд, не эмулятор пользователя.
