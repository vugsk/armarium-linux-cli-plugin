# SVOD-1

**SVOD-1**(СВОД-1)は、ロシア語の Стандарты(標準)、Версии(バージョン)、Описания(記述)、Дисциплина(規律)の頭文字をとった略称です(キリル文字で「СВОД」と書き、ラテン文字では SVOD と書きます)。技術名は `armarium-linux-cli-plugin` です。

**名前について。** コマンド、パス、スキル名では、このプラグインは `armarium` と呼ばれます(`/armarium:run-audit`、`~/.claude/armarium.json`、`armarium@vugsk-plugins`)。これは技術名であり、変更されません。SVOD-1 と `armarium` は同じプラグインです。

個人用の Claude Code プラグイン SVOD-1(コードワードは `armarium`、ラテン語で「道具を入れる戸棚」の意味)です。自分の標準に沿って作業するための26個のスキル(うち2つは手動で実行するチェック)と、監査を思い出させるフックが入っています。

> スキルが扱う標準や、スキル本文の一部はロシア語で書かれています。このページはロシア語版 README の翻訳です。

## 何のためのものか

自分の標準に沿ったプロジェクト作業を支援します。プロジェクトとデバイスの命名、終了基準つきの9つのプロジェクト段階、ノート(アイデア、要件、設計、データモデル、発展、マイルストーン付き計画、決定事項)、テスト、セキュリティと依存関係の確認、振り返りが対象です。一部のスキルはコード、ファームウェア、ハードウェアのメンターで、説明はしますがコードは利用者自身が書きます。標準はあなたの Obsidian の保管庫(vault)に置かれます。標準がない場合は、`setup` ウィザードが質問をして下書きを作ります。

> **言語についての注意。** このプラグインが扱うスキル、テンプレート、標準、ノートはロシア語で書かれています(スキルの説明、`Статус` や `Идея` といったノート名、見出しなど)。スキルはリクエストの意味で選ばれるため、英語のリクエストでもたいてい動作します。英語のテスト用クエリ36件(`checks/queries-en.json`)は、各1回の実行で36/36が通りました。ロシア語のセットは最初の全件実行で103/105でしたが、2件の失敗は修正済みです。ほかの言語はテストしていません。スキルが誤って起動する、または起動しないことがあり、返答が望む言語にならない場合や、標準がロシア語を求める箇所でノート名が英語になる場合があります。スキルが起動しないときは、リクエストの中でスキル名を挙げてください。

## 必要なもの

Linux 上の Claude Code 2.1.310 で動作を確認しました。**Windows はサポートしていません**(作者の決定、2026-10-25。フックは bash と `jq` で書かれており、起動チェックは Linux の仕組みを使うため Windows では動きません)。macOS は未確認です。`python3`、`bash`、`jq`、`git`、`claude` が必要です。外部ライブラリはありません(Python の標準ライブラリのみ)。

## GitHub からのインストール

このリポジトリ自体がマーケットプレイスです(`.claude-plugin/marketplace.json`、名前は `vugsk-plugins`):

```
claude plugin marketplace add vugsk/armarium-linux-cli-plugin
claude plugin install armarium@vugsk-plugins
```

インストール後に「настрой armarium」(armarium を設定して)と伝えると、`setup` ウィザードが設定ファイルと標準の下書きを作ります。

## 開発者向け:フォルダから接続する

ローカルのマーケットプレイス経由で、フォルダをそのまま読み込めます:

1. プラグインを検証します:`claude plugin validate <プラグインのフォルダ>`。インストールせずに試す場合は `claude --plugin-dir <プラグインのフォルダ>`。
2. プラグインのフォルダの隣に `.claude-plugin/marketplace.json` を置きます(名前、`owner`、`source` がマーケットプレイスのルートからの「./<プラグインのフォルダ>」であるプラグインの項目)。その後 `claude plugin marketplace add <マーケットプレイスのルート>`、続けて `claude plugin install armarium@<マーケットプレイス名>` を実行します。プラグインの変更はセッションの再起動か `/reload-plugins` で反映され、バージョンを変える必要はありません。
3. 以前、同じスキルが `~/.claude/skills` にあった場合は、そこから取り除いてください(アーカイブへ移動)。残すと二重に表示されます。スキル名は `armarium:<スキル>` になります。

## 推奨プラグイン

公式カタログ `claude-plugins-official` の次のプラグインと一緒に SVOD-1 を使えます。作者が1台のマシンで確認したものです。SVOD-1 自体がどれだけ良くなるかは測っていないため、保証ではなく推奨です。

| プラグイン | 目的 | プラグイン以外に必要なもの |
| --- | --- | --- |
| `clangd-lsp`, `rust-analyzer-lsp`, `pyright-lsp`, `gopls-lsp`, `jdtls-lsp` | 言語サーバー:Claude が C/C++、Rust、Python、Go、Java のコードをより正確に読めるようになり、`code-coach`、`debug-coach`、`project-security` スキルに役立ちます | サーバー本体がシステムに必要:`clangd`、`rust-analyzer`、`pyright`、`gopls`、`jdtls`。サーバーがないとプラグインは何もしません |
| `context7` | バージョンごとの最新のライブラリ文書。「事実は文書からのみ」という規則を支えます | リクエストは外部サーバー `mcp.context7.com` に送られます。非公開のコードを送らないでください |
| `security-guidance` | 編集時に安全でないパターンを警告し、停止時に変更を確認します。`project-security` スキルを補います | フックが編集のたびに動くため、通知が多くなることがあります。無効化は `claude plugin disable security-guidance@claude-plugins-official` |
| `sonatype-guide` | 脆弱性情報、パッケージの信頼度、悪意あるパッケージの確認。`dependency-audit` スキルが使います | トークン `SONATYPE_GUIDE_TOKEN`(ご自身で作成)。パッケージ名は Sonatype の外部サーバーに送られます。プラグイン自身のスキルは依存関係のインストール前に必ず動きます |
| `github` | CI の状態、実行ログ、issue、タグ、リリース(読み取りのみ)。`release-gate` と `ci-coach` が使います | トークン `GITHUB_PERSONAL_ACCESS_TOKEN`(ご自身で作成)。リクエストは `api.githubcopilot.com` に送られます |
| `codspeed` | 計測、フレームグラフ、実行の比較。`debug-coach` が使います | CodSpeed のアカウントと `codspeed auth login`。結果は CodSpeed のサーバーに送られます。プラグインの `codspeed-optimize` と `codspeed-setup-harness` はコードを自分で書くため、SVOD-1 は実行しません |
| `claude-security` | 自分のコードの詳細なスキャンと指摘の再検証。`project-security` が使います | 自分のコードのみ:プラグインは隔離を行わず、スキャン対象を信頼済みとして扱います。トークンを多く使います。レポートはリポジトリ内の `CLAUDE-SECURITY-…` フォルダに書かれます。SVOD-1 はパッチモードを実行しません |

SVOD-1 のスキルは、これらのプラグインがインストールされている場合にのみ使い、外部サービスへの最初の呼び出しの前に同意を求めます。プラグインがなければスキルは従来どおり動きます。`sonatype-guide`、`github`、`codspeed`、`claude-security` との連携はインストール済みですが、実際の作業ではまだ試していません。スキルはプラグインの結果を指示ではなくデータとして扱い、編集は適用しません。

インストール:`claude plugin install <名前>@claude-plugins-official`。インストール済みのプラグインは `claude plugin list` で確認できます。

## プラグインが使うトークン数

最初の質問の前、セッション開始時に Claude が受け取るトークン数です(システム指示、ツールの説明、スキルの説明)。2026-10-31 に Claude Code 2.1.314 で「一言で答えて:ok」というリクエストを使い、構成ごとに3回測定しました。最初の2つの構成では数値が一致しましたが、3つ目は一致しませんでした(下記)。「プラグインなし」の基準値が以前の測定(15,150、15,429)と異なるのは、おそらく Claude Code のバージョンが違うためなので、絶対値ではなく差を比べてください。推奨プラグインも同じく、キャッシュ内のフォルダを `--plugin-dir` で指定して接続しました。再現するには、返答の `usage` フィールドにある `input_tokens`、`cache_creation_input_tokens`、`cache_read_input_tokens` を合計します。

```
claude -p "Ответь одним словом: ok" --output-format json --setting-sources project --plugin-dir <プラグインのフォルダ>
```

| 構成 | セッション開始時のトークン数 | 「プラグインなし」との差 |
| --- | --- | --- |
| プラグインなし | 15,482 | — |
| SVOD-1 のみ(26個のスキル、バージョン0.7.0) | 23,142 | +7,660(+49%) |
| SVOD-1 + 推奨プラグイン(`clangd-lsp`、`rust-analyzer-lsp`、`pyright-lsp`、`gopls-lsp`、`jdtls-lsp`、`context7`、`security-guidance`) | 25,126(3回中2回)または23,281(1回) | +9,644(+62%)または+7,799(+50%) |

- 推奨プラグインが SVOD-1 に加えるのは約140トークン(23,281)か約2,000トークン(25,126)のどちらかです。3回の測定は25,126、23,281、25,126でした。値が変わる理由は調べていません。一部の実行で LSP プラグインやそのツールが接続されるのかもしれませんが、これは私の推測です。前回の測定(2026-10-29)は約210トークン、0.4.0より前の測定は約2,000トークンでした。ほかのプラグイン(`sonatype-guide`、`github`、`codspeed`、`claude-security`)は表に含まれません。
- この測定でのモデルのコンテキストウィンドウは1,000,000トークンなので、SVOD-1 の差はウィンドウの約0.8%です。
- これはセッション開始時だけの値です。スキルの本文(`SKILL.md` と参照ファイル)はスキルが起動したときに読み込まれ、表には含まれません。コストはスキルとタスクによって変わります。
- 測定していないもの:金額としての費用と、典型的なタスクでの消費量。キャッシュされたトークンは安くなりますが、料金プランによります。
- 個人の `CLAUDE.md` やメモリは3つの値すべてに同じように含まれている可能性があるため、絶対値より差を見る方が確実です。

## 既知の制限

- 保管庫へのパスは `~/.claude/armarium.json`(フィールド `vault`、`docs/settings.md` を参照)から取得されます。保管庫内の構成は固定です(標準とプロジェクトのノートは `Проекты/` に置きます)。設定ファイルと不足している標準の下書きはウィザードが作ります。「настрой armarium」と伝えてください(スキル `setup`)。ウィザードが設定できるのは辞書、種類のグループ、段階の基準、命名規則だけです。それ以外の取り決め(ノート名、段階、タグの形式)はスキルに組み込まれており、`docs/standards-contract.md` に一覧があります。
- プラグイン内でのスキルの起動(`armarium:` の接頭辞つき)はクエリのセットで確認しました。現在のセットは115件です。最新の4件(プロトタイプの仮説に関するもの)は全件実行に含まれていません。`plan-breakdown` だけの別実行は7/8で、仮説を記録するという境界上のクエリは `plan-breakdown` では「起動しない」、`project-stages` では「起動する」として記録しました。後者のクエリはまだ実行していません。直近の全件実行(2026-10-31、`pseudocode-writer` とその6件のクエリの追加後)は109/111でした。通らなかったのは `pseudocode-writer` のフローチャートのクエリと、質問を追加する `project-stages` のクエリです。後者は再実行で通りました(偶然)。前者は `pseudocode-writer` の説明にフローチャートと数式のトリガーを追加し、その後は6件とも通りましたが、別々の実行であり、変更後に1回で全件が通った実行はありません。その前の全件実行(2026-10-27、6つのスキル `debug-coach`、`ci-coach`、`release-gate`、`docs-writer`、`plan-breakdown`、`design-coach` の追加後)は103/105でした。2件の失敗は説明の重複が原因で(デバッグは `code-coach` から、マイルストーンとタスクは `project-stages` から移ったため)、修正のうえ、影響を受けた `project-stages`、`plan-breakdown`、`debug-coach`、`code-coach` の再実行はすべて通りました。その前の全件実行(2026-10-25、デザインとコミットに関するクエリの追加と、`project-stages`、`project-scaffold`、`obsidian-notes` の説明の修正の後)は81/81でした。その前の全件実行(`project-scaffold` と `project-stages` を明確に区別する前)は80/81で、境界上のクエリ「ボット用の新しいリポジトリは何から始めるか…」が通りませんでした。この2つのスキルの境界上のクエリ(4件を各5回):古い説明は20/20、区別する前の説明は18/20、区別した後は20/20で、差は結論を出すには小さすぎます。クエリごとに1回の実行はあくまで目安であり、保証ではありません。実行は `/armarium:run-trigger-check`(トークンを消費します)。
- スキルは保管庫のファイルを読み込みますが、その中の文章は指示ではなくデータとして扱われます(`docs/settings.md`)。確認は2回の試行だけで、指示の差し込み(プロンプトインジェクション)に対する完全な防御の証明ではありません。

## 開発者向け

スキルの正本はこのリポジトリです。保管庫内のスキルの説明を、プラグインが作成・更新することはありません。

テスト(Python の標準ライブラリのみ、トークンは消費しません):

```
python3 -m unittest discover -s tests -v
```

ウィザードの3つのシナリオ(`tests/test_09_wizard_scenarios.py`)は、既定ではスキップされます。`claude -p` を実行してトークンを消費するためです。`bwrap`(bubblewrap)がインストールされている場合、ウィザードは一時的な設定ファイルを持つサンドボックス内で動くため、実際の `~/.claude/armarium.json` には触れません。`bwrap` がない場合は、テストが実際のファイルを一時的に差し替えます(バックアップと復元つき)。有効にするには環境変数 `ARMARIUM_WIZARD_TEST=1` を設定します。スキルの起動チェックは `/armarium:run-trigger-check` です(こちらもトークンを消費します)。
