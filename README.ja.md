# SVOD-1

**SVOD-1**(СВОД-1)は、ロシア語の Стандарты(標準)、Версии(バージョン)、Описания(記述)、Дисциплина(規律)の頭文字をとった略称です(キリル文字で「СВОД」と書き、ラテン文字では SVOD と書きます)。技術名は `armarium-linux-cli-plugin` です。

**名前について。** コマンド、パス、スキル名では、このプラグインは `armarium` と呼ばれます(`/armarium:run-audit`、`~/.claude/armarium.json`、`armarium@vugsk-plugins`)。これは技術名であり、変更されません。SVOD-1 と `armarium` は同じプラグインです。

個人用の Claude Code プラグイン SVOD-1(コードワードは `armarium`、ラテン語で「道具を入れる戸棚」の意味)です。自分の標準に沿って作業するための25個のスキル(うち2つは手動で実行するチェック)と、監査を思い出させるフックが入っています。

> スキルが扱う標準や、スキル本文の一部はロシア語で書かれています。このページはロシア語版 README の翻訳です。

## 何のためのものか

自分の標準に沿ったプロジェクト作業を支援します。プロジェクトとデバイスの命名、終了基準つきの9つのプロジェクト段階、ノート(アイデア、要件、設計、データモデル、発展、マイルストーン付き計画、決定事項)、テスト、セキュリティと依存関係の確認、振り返りが対象です。一部のスキルはコード、ファームウェア、ハードウェアのメンターで、説明はしますがコードは利用者自身が書きます。標準はあなたの Obsidian の保管庫(vault)に置かれます。標準がない場合は、`setup` ウィザードが質問をして下書きを作ります。

## 必要なもの

Linux 上の Claude Code 2.1.310 で動作を確認しました。**Windows はサポートしていません**(作者の決定、2026-10-25。フックは bash と `jq` で書かれており、起動チェックは Linux の仕組みを使うため Windows では動きません)。macOS は未確認です。`python3`、`bash`、`jq`、`git`、`claude` が必要です。外部ライブラリはありません(Python の標準ライブラリのみ)。

## GitHub からのインストール

このリポジトリ自体がマーケットプレイスです(`.claude-plugin/marketplace.json`、名前は `vugsk-plugins`):

```
claude plugin marketplace add vugsk/armarium-linux-cli-plugin
claude plugin install armarium@vugsk-plugins
```

インストール後に「настрой armarium」(armarium を設定して)と伝えると、`setup` ウィザードが設定ファイルと標準の下書きを作ります。

## 開発者向け:フォルダから接続する

ローカルのマーケットプレイス経由で、フォルダをそのまま読み込めます:

1. プラグインを検証します:`claude plugin validate <プラグインのフォルダ>`。インストールせずに試す場合は `claude --plugin-dir <プラグインのフォルダ>`。
2. プラグインのフォルダの隣に `.claude-plugin/marketplace.json` を置きます(名前、`owner`、`source` がマーケットプレイスのルートからの「./<プラグインのフォルダ>」であるプラグインの項目)。その後 `claude plugin marketplace add <マーケットプレイスのルート>`、続けて `claude plugin install armarium@<マーケットプレイス名>` を実行します。プラグインの変更はセッションの再起動か `/reload-plugins` で反映され、バージョンを変える必要はありません。
3. 以前、同じスキルが `~/.claude/skills` にあった場合は、そこから取り除いてください(アーカイブへ移動)。残すと二重に表示されます。スキル名は `armarium:<スキル>` になります。

## 推奨プラグイン

公式カタログ `claude-plugins-official` の次のプラグインと一緒に SVOD-1 を使えます。作者が1台のマシンで確認したものです。SVOD-1 自体がどれだけ良くなるかは測っていないため、保証ではなく推奨です。

| プラグイン | 目的 | プラグイン以外に必要なもの |
| --- | --- | --- |
| `clangd-lsp`, `rust-analyzer-lsp`, `pyright-lsp`, `gopls-lsp`, `jdtls-lsp` | 言語サーバー:Claude が C/C++、Rust、Python、Go、Java のコードをより正確に読めるようになり、`code-coach` スキルに役立ちます | サーバー本体がシステムに必要:`clangd`、`rust-analyzer`、`pyright`、`gopls`、`jdtls`。サーバーがないとプラグインは何もしません |
| `context7` | バージョンごとの最新のライブラリ文書。「事実は文書からのみ」という規則を支えます | リクエストは外部サーバー `mcp.context7.com` に送られます。非公開のコードを送らないでください |
| `security-guidance` | 編集時に安全でないパターンを警告し、停止時に変更を確認します。`project-security` スキルを補います | フックが編集のたびに動くため、通知が多くなることがあります。無効化は `claude plugin disable security-guidance@claude-plugins-official` |

インストール:`claude plugin install <名前>@claude-plugins-official`。インストール済みのプラグインは `claude plugin list` で確認できます。

## プラグインが使うトークン数

最初の質問の前、セッション開始時に Claude が受け取るトークン数です(システム指示、ツールの説明、スキルの説明)。2026-10-25 に Claude Code 2.1.310 で「一言で答えて:ok」というリクエストを使い、構成ごとに3回測定しました。数値は一致しました。再現するには、返答の `usage` フィールドにある `input_tokens`、`cache_creation_input_tokens`、`cache_read_input_tokens` を合計します。

```
claude -p "Ответь одним словом: ok" --output-format json --setting-sources project --plugin-dir <プラグインのフォルダ>
```

| 構成 | セッション開始時のトークン数 | 「プラグインなし」との差 |
| --- | --- | --- |
| プラグインなし | 15,150 | — |
| SVOD-1 のみ(19個のスキル、0.4.0より前の計測) | 19,994 | +4,844(+32%) |
| SVOD-1 + 推奨プラグイン(`clangd-lsp`、`rust-analyzer-lsp`、`pyright-lsp`、`gopls-lsp`、`jdtls-lsp`、`context7`、`security-guidance`) | 21,977 | +6,827(+45%) |

- 推奨プラグインは SVOD-1 にさらに約2,000トークンを加えます。個別の測定:SVOD-1 + `context7` のみ — 21,977、SVOD-1 + 残りの6個(言語サーバーと `security-guidance`)— 21,687。これらの数値は足し合わせても一致せず(全部入れると `context7` だけの場合と同じ値になります)、理由は調べていないため、信頼できるのは全プラグイン合計の値だけです。
- この測定でのモデルのコンテキストウィンドウは1,000,000トークンなので、SVOD-1 はウィンドウの約0.5%を使います。
- これはセッション開始時だけの値です。スキルの本文(`SKILL.md` と参照ファイル)はスキルが起動したときに読み込まれ、表には含まれません。コストはスキルとタスクによって変わります。
- 測定していないもの:金額としての費用と、典型的なタスクでの消費量。キャッシュされたトークンは安くなりますが、料金プランによります。
- 個人の `CLAUDE.md` やメモリは3つの値すべてに同じように含まれている可能性があるため、絶対値より差を見る方が確実です。

## 既知の制限

- 保管庫へのパスは `~/.claude/armarium.json`(フィールド `vault`、`docs/settings.md` を参照)から取得されます。保管庫内の構成は固定です(標準とプロジェクトのノートは `Проекты/` に置きます)。設定ファイルと不足している標準の下書きはウィザードが作ります。「настрой armarium」と伝えてください(スキル `setup`)。ウィザードが設定できるのは辞書、種類のグループ、段階の基準、命名規則だけです。それ以外の取り決め(ノート名、段階、タグの形式)はスキルに組み込まれており、`docs/standards-contract.md` に一覧があります。
- プラグイン内でのスキルの起動(`armarium:` の接頭辞つき)は81件のクエリで確認しました。直近の全件実行(2026-10-25、デザインとコミットに関するクエリの追加と、`project-stages`、`project-scaffold`、`obsidian-notes` の説明の修正の後)は81/81でした。その前の全件実行(`project-scaffold` と `project-stages` を明確に区別する前)は80/81で、境界上のクエリ「ボット用の新しいリポジトリは何から始めるか…」が通りませんでした。この2つのスキルの境界上のクエリ(4件を各5回):古い説明は20/20、区別する前の説明は18/20、区別した後は20/20で、差は結論を出すには小さすぎます。クエリごとに1回の実行はあくまで目安であり、保証ではありません。実行は `/armarium:run-trigger-check`(トークンを消費します)。
- スキルは保管庫のファイルを読み込みますが、その中の文章は指示ではなくデータとして扱われます(`docs/settings.md`)。確認は2回の試行だけで、指示の差し込み(プロンプトインジェクション)に対する完全な防御の証明ではありません。
- ライセンス:MIT、著作権者は `vugsk`(ファイル `LICENSE`、`plugin.json` の `license` フィールド)。

## 開発者向け

スキルの正本はこのリポジトリです。保管庫内のスキルの説明を、プラグインが作成・更新することはありません。

テスト(Python の標準ライブラリのみ、トークンは消費しません):

```
python3 -m unittest discover -s tests -v
```

ウィザードの3つのシナリオ(`tests/test_09_wizard_scenarios.py`)は、既定ではスキップされます。`claude -p` を実行してトークンを消費するためです。`bwrap`(bubblewrap)がインストールされている場合、ウィザードは一時的な設定ファイルを持つサンドボックス内で動くため、実際の `~/.claude/armarium.json` には触れません。`bwrap` がない場合は、テストが実際のファイルを一時的に差し替えます(バックアップと復元つき)。有効にするには環境変数 `ARMARIUM_WIZARD_TEST=1` を設定します。スキルの起動チェックは `/armarium:run-trigger-check` です(こちらもトークンを消費します)。
