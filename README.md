# СВОД-1

**СВОД-1** (SVOD-1) — Стандарты, Версии, Описания, Дисциплина. Техническое имя: `armarium-linux-cli-plugin`.

**Про имена.** В командах, путях и именах скиллов плагин называется `armarium` (`/armarium:run-audit`, `~/.claude/armarium.json`, `armarium@vugsk-plugins`): это техническое имя, оно не меняется. СВОД-1 и `armarium` — один и тот же плагин.

Личный плагин Claude Code СВОД-1 (кодовое слово `armarium`, по-латыни «шкаф для инструментов»): 19 скиллов для работы по личным стандартам (два из них — ручные запуски проверок) и хук-напоминание про аудит.

## Зачем это нужно

Плагин ведёт работу над проектами по вашим же стандартам: имена проектов и устройств, шесть этапов проекта с критериями выхода, заметки (идея, требования, архитектура, план с вехами, решения), тесты, проверка безопасности и зависимостей, итоги. Часть скиллов — наставники по коду, прошивкам и железу: они объясняют, а код пишет пользователь. Стандарты лежат в вашем хранилище Obsidian. Если их нет, мастер `setup` задаст вопросы и создаст черновики.

## Требования

Проверено на Linux с Claude Code 2.1.310. **Windows не поддерживается** (решение автора 2026-10-25; хук написан на bash и `jq`, а проверка срабатывания использует механизмы Linux и в Windows не заработает), macOS не проверялась. Нужны программы `python3`, `bash`, `jq`, `git` и `claude`. Внешних библиотек у плагина нет (только стандартная библиотека Python).

## Что внутри

| Папка | Что это |
| --- | --- |
| `skills/` | 19 скиллов: имена и этапы проектов, наставники по коду, прошивкам и железу, проверка платы, тесты, безопасность, зависимости, реверс-инженерия, итоги проекта, аудит стандартов, мастер настройки `setup`, ручные запуски `run-audit` (проверка согласованности) и `run-trigger-check` (проверка срабатывания скиллов, тратит токены, спрашивает подтверждение) |
| `docs/` | справки для скиллов: `settings.md` (файл настроек `~/.claude/armarium.json`), `standards-contract.md` (контракт структуры стандартов для мастера), `question-rounds.md` (правило опроса пользователя раундами) |
| `hooks/` | `audit-reminder.sh` и `hooks.json`: после правки стандарта или скилла напоминает предложить `standards-audit` |
| `checks/` | набор проверок: `queries.json`, `run_trigger.py`, `make_fixtures.py`, описание и сценарии |
| `tests/` | тесты плагина (запуск описан в разделе «Для разработки») |

Стандарты (`Стандарт по названию проектов.md`, `Стандарт по названию устройств.md`, `Стандарт проектных заметок.md`) лежат в папке `Проекты/` вашего хранилища (корень хранилища указан в `~/.claude/armarium.json`), не в плагине: скиллы читают их оттуда.

## Скиллы

| Скилл | Что делает |
| --- | --- |
| `setup` | мастер первой настройки: находит хранилище Obsidian, создаёт файл настроек и черновики недостающих стандартов |
| `project-stages` | ведёт новый проект по шести этапам и заметкам в Obsidian (статус, вопросы, план, решения) и общей карте проектов; код не пишет |
| `naming-standards` | имена проектов и устройств по стандартам: кодовое слово, публичное имя, ветки `gen-N`, теги |
| `obsidian-notes` | оформление заметок: чертежи Excalidraw вместо ASCII, диаграммы Mermaid, раскладка по папкам, фиксация решений |
| `project-scaffold` | наставник по заготовке репозитория: структура папок, ветка `gen-1`, README, лицензия, CI |
| `repo-init` | создаёт заготовку папки с кодом (README, `.gitignore`, hello-world, `tests/`, лицензия) и проверяет совместимость лицензий |
| `release-versioning` | версии и релизы: SemVer, Conventional Commits, теги, release-please, сообщения коммитов |
| `code-coach` | наставник по Rust, C++, C, Python, Go, Java, ассемблеру и git: объясняет, код пишет пользователь |
| `firmware-esp-stm` | наставник по прошивкам для ESP и STM32: сборка, прошивка, отладка, периферия |
| `hw-design-coach` | наставник по проектированию схем и плат: питание, трассировка, ERC/DRC, платы на ESP и STM32, свой процессор |
| `hw-board-check` | проверка платы перед заказом: ERC/DRC, требования производства, ревизии, паспорт изделия |
| `test-plan` | проверка проекта на этапе 4: пишет и запускает тесты в `tests/`, ведёт заметку «Проверки» |
| `project-security` | проверка безопасности кода проекта на этапе 4; результат записывает заметкой «Безопасность» |
| `dependency-audit` | выбор и проверка зависимостей на уязвимости и ошибки, ранжирование кандидатов |
| `reverse-engineering` | анализ бинарников, прошивок, форматов и протоколов для законных целей |
| `project-retro` | итоговая заметка при заморозке, отмене или выпуске проекта |
| `standards-audit` | проверка согласованности стандартов и скиллов; только отчёт, ничего не правит |
| `run-audit` | ручной запуск проверки согласованности: `/armarium:run-audit` |
| `run-trigger-check` | ручная проверка срабатывания скиллов: `/armarium:run-trigger-check` (тратит токены, спрашивает подтверждение) |

## Установка из GitHub

Репозиторий сам является marketplace (`.claude-plugin/marketplace.json`, имя `vugsk-plugins`):

```
claude plugin marketplace add vugsk/armarium-linux-cli-plugin
claude plugin install armarium@vugsk-plugins
```

После установки скажите «настрой armarium»: мастер `setup` создаст файл настроек и черновики стандартов.

## Для разработки: подключение из папки

Плагин можно читать из папки на месте через локальный marketplace:

1. Проверьте плагин: `claude plugin validate <папка плагина>`; на пробу без установки: `claude --plugin-dir <папка плагина>`.
2. Положите рядом с папкой плагина файл `.claude-plugin/marketplace.json` (имя, `owner`, запись плагина с `source` «./<папка плагина>» от корня marketplace) и выполните `claude plugin marketplace add <корень marketplace>`, затем `claude plugin install armarium@<имя marketplace>`. Правки плагина видны после перезапуска сеанса или `/reload-plugins`, версию менять не нужно.
3. Если раньше те же скиллы лежали в `~/.claude/skills`, уберите их оттуда (перенесите в архив), иначе они задвоятся. Имена скиллов станут `armarium:<скилл>`.

## Рекомендуемые плагины

Можно использовать СВОД-1 вместе с этими плагинами из официального каталога `claude-plugins-official`. Проверено автором на одной машине; как сильно они улучшают именно СВОД-1, не измерялось, это рекомендация, а не гарантия.

| Плагин | Зачем | Что нужно помимо плагина |
| --- | --- | --- |
| `clangd-lsp`, `rust-analyzer-lsp`, `pyright-lsp`, `gopls-lsp`, `jdtls-lsp` | серверы языков: Claude точнее читает код C/C++, Rust, Python, Go и Java, что полезно скиллу `code-coach` | сами серверы в системе: `clangd`, `rust-analyzer`, `pyright`, `gopls`, `jdtls`; плагин без сервера ничего не делает |
| `context7` | актуальная документация библиотек по версиям; помогает правилу «факты только из документации» | запросы уходят на внешний сервер `mcp.context7.com`: не отправляйте через него приватный код |
| `security-guidance` | предупреждения о небезопасных паттернах при правках, проверка изменений при остановке; дополняет скилл `project-security` | хуки срабатывают на каждую правку и могут давать шум; отключается `claude plugin disable security-guidance@claude-plugins-official` |

Установка: `claude plugin install <имя>@claude-plugins-official`. Установленные плагины видны командой `claude plugin list`.

## Сколько токенов занимает плагин

Столько токенов Claude получает в начале сессии, до вашего первого вопроса (системные инструкции, описания инструментов и скиллов). Измерено на Claude Code 2.1.310 запросом «ответь одним словом: ok», по три запуска на каждую конфигурацию; числа совпали. Повторить можно так: сложите `input_tokens`, `cache_creation_input_tokens` и `cache_read_input_tokens` из поля `usage` ответа.

```
claude -p "Ответь одним словом: ok" --output-format json --setting-sources project --plugin-dir <папка плагина>
```

| Конфигурация | Токенов в начале сессии | Разница с «без плагинов» |
| --- | --- | --- |
| Без плагинов | 15 150 | — |
| Только СВОД-1 (19 скиллов) | 19 994 | +4 844 (+32 %) |
| СВОД-1 + рекомендуемые (`clangd-lsp`, `rust-analyzer-lsp`, `pyright-lsp`, `gopls-lsp`, `jdtls-lsp`, `context7`, `security-guidance`) | 21 977 | +6 827 (+45 %) |

- Рекомендуемые плагины добавляют к СВОД-1 ещё около 2 000 токенов. Отдельные замеры: СВОД-1 + только `context7` — 21 977, СВОД-1 + остальные шесть (серверы языков и `security-guidance`) — 21 687. Эти числа не складываются (вместе выходит столько же, сколько с одним `context7`); причину я не выяснял, поэтому надёжна только цифра по всем плагинам вместе.
- Окно контекста у модели в этом измерении — 1 000 000 токенов, так что СВОД-1 занимает около 0,5 % окна.
- Это только начало сессии. Текст скилла (тело `SKILL.md` и справки) подгружается, когда скилл сработал, и в таблицу не входит; цена зависит от скилла и задачи.
- Не измерялось: стоимость в деньгах и расход на типовых задачах. Токены из кеша стоят дешевле, но это зависит от вашего тарифа.
- Ваш личный `CLAUDE.md` и память могут входить во все три значения одинаково, поэтому надёжнее смотреть на разницу, а не на абсолютные числа.

## Известные ограничения

- Пути к хранилищу берутся из `~/.claude/armarium.json` (поле `vault`, см. `docs/settings.md`); раскладка внутри хранилища фиксирована (стандарты и заметки проектов в `Проекты/`). Файл настроек и черновики недостающих стандартов создаёт мастер: скажите «настрой armarium» (скилл `setup`). Мастер настраивает только словари, группы типов, критерии этапов и правила имён; остальные соглашения (имена заметок, этапы, форматы тегов) зашиты в скиллах и перечислены в `docs/standards-contract.md`.
- Срабатывание скиллов в плагине (с префиксом `armarium:`) проверялось набором из 81 запроса: последний полный прогон (2026-10-25, после добавления запросов про дизайн и коммиты и правки описаний `project-stages`, `project-scaffold` и `obsidian-notes`) дал 81/81. Предыдущий полный прогон, до явного разведения `project-scaffold` и `project-stages`, дал 80/81: не прошёл пограничный запрос «с чего начать новый репозиторий для бота…». Пограничные запросы этих двух скиллов (4 запроса по 5 повторов): старое описание 20/20, описание до разведения 18/20, после разведения 20/20; разница слишком мала для вывода. Один запуск на запрос — только сигнал, не гарантия. Запуск: `/armarium:run-trigger-check` (тратит токены).
- Скиллы читают файлы хранилища; текст в них считается данными, а не указаниями (`docs/settings.md`). Проверено двумя пробами, не доказательство полной защиты от подмены указаний.
- Лицензия: MIT, правообладатель `vugsk` (файл `LICENSE`, поле `license` в `plugin.json`).

## Для разработки

Источник скиллов — этот репозиторий. Описаний скиллов в хранилище плагин не создаёт и не обновляет.

Тесты (стандартная библиотека Python, токены не тратятся):

```
python3 -m unittest discover -s tests -v
```

Три сценария мастера настройки (`tests/test_09_wizard_scenarios.py`) по умолчанию пропускаются: они запускают `claude -p` и тратят токены. Если установлен `bwrap` (bubblewrap), мастер работает в песочнице с временным файлом настроек, и ваш настоящий `~/.claude/armarium.json` не затрагивается; без `bwrap` тест на время подменяет настоящий файл (с копией и возвратом) Включаются переменной `ARMARIUM_WIZARD_TEST=1`. Проверка срабатывания скиллов — `/armarium:run-trigger-check` (тоже тратит токены).
