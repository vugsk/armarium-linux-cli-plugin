# armarium-linux-cli-plugin

Личный плагин Claude Code «armarium» (латынь: шкаф для инструментов): 16 скиллов для работы по личным стандартам, хук-напоминание про аудит и две команды. Публичного имени пока нет.

## Что внутри

| Папка | Что это |
| --- | --- |
| `skills/` | 16 скиллов: имена и этапы проектов, наставники по коду, прошивкам и железу, проверка платы, тесты, безопасность, зависимости, реверс-инженерия, итоги проекта, аудит стандартов |
| `hooks/` | `audit-reminder.sh` и `hooks.json`: после правки стандарта или скилла напоминает предложить `standards-audit` и обновить копию |
| `commands/` | `/armarium:audit` (проверка согласованности) и `/armarium:trigger-check` (проверка срабатывания скиллов, тратит токены, спрашивает подтверждение) |
| `checks/` | набор проверок: `queries.json`, `run_trigger.py`, `make_fixtures.py`, описание и сценарии |
| `tools/` | `make_vault_copy.py` (копия и описания в хранилище Obsidian), `import_user_skills.py` (переходный помощник) |

Стандарты (`Стандарт по названию проектов.md`, `Стандарт по названию устройств.md`, `Стандарт проектных заметок.md`) лежат в хранилище `Book/Проекты`, не в плагине: скиллы читают их оттуда.

## Источник истины

Источник — этот плагин. Резервная копия и описания в `Book/Документация/Скиллы Claude/` строятся из него:

```
python3 -I tools/make_vault_copy.py
```

**Переходный период.** Пока плагин не включён, Claude Code читает скиллы из `~/.claude/skills`, и правки идут туда. После правки там сначала:

```
python3 -I tools/import_user_skills.py     # перенести правки из ~/.claude/skills в плагин
python3 -I tools/make_vault_copy.py        # затем обновить копию в хранилище
```

## Как включить (когда решите)

1. Проверьте плагин: `claude plugin validate ~/Projects/claude/armarium-linux-cli-plugin` (проходит) и запустите `claude --plugin-dir ~/Projects/claude/armarium-linux-cli-plugin` на пробу.
2. Чтобы не было дублей, на время работы плагина уберите из `~/.claude/skills` те же 16 скиллов (или переименуйте папку) и удалите из `~/.claude/settings.json` ручной хук `audit-reminder.sh`, он есть в `hooks/hooks.json` плагина. Имена скиллов станут `armarium:<скилл>`.

## Рекомендуемые плагины

Автор использует `armarium` вместе с этими плагинами из официального каталога `claude-plugins-official`. Автор подтвердил, что они работают на его машине (2026-10-24); как сильно они улучшают именно `armarium`, не измерялось, это рекомендация, а не гарантия.

| Плагин | Зачем | Что нужно помимо плагина |
| --- | --- | --- |
| `clangd-lsp`, `rust-analyzer-lsp`, `pyright-lsp`, `gopls-lsp`, `jdtls-lsp` | серверы языков: Claude точнее читает код C/C++, Rust, Python, Go и Java, что полезно скиллу `code-coach` | сами серверы в системе: `clangd`, `rust-analyzer`, `pyright`, `gopls`, `jdtls`; плагин без сервера ничего не делает |
| `context7` | актуальная документация библиотек по версиям; помогает правилу «факты только из документации» | запросы уходят на внешний сервер `mcp.context7.com`: не отправляйте через него приватный код |
| `security-guidance` | предупреждения о небезопасных паттернах при правках, проверка изменений при остановке; дополняет скилл `project-security` | хуки срабатывают на каждую правку и могут давать шум; отключается `claude plugin disable security-guidance@claude-plugins-official` |

Установка: `claude plugin install <имя>@claude-plugins-official`. Установленные плагины видны командой `claude plugin list`.

## Известные ограничения

- В скиллах и хуке прописаны пути вашей машины (`/home/germanf0x/...`), для другой машины плагин нужно править.
- Скилл `standards-audit` ищет скиллы в `~/.claude/skills`. После переноса в плагин его нужно поправить, чтобы он читал `skills/` плагина.
- Срабатывание скиллов в плагине (с префиксом `armarium:`) не проверялось.
