# СВОД-1

**СВОД-1** (SVOD-1) — Стандарты, Версии, Описания, Дисциплина. Техническое имя: `armarium-linux-cli-plugin`.

**Про имена.** В командах, путях и именах скиллов плагин называется `armarium` (`/armarium:run-audit`, `~/.claude/armarium.json`, `armarium@vugsk-plugins`): это техническое имя, оно не меняется. СВОД-1 и `armarium` — один и тот же плагин.

Личный плагин Claude Code СВОД-1 (кодовое слово `armarium`, по-латыни «шкаф для инструментов»): 26 скиллов для работы по личным стандартам (два из них — ручные запуски проверок) и хук-напоминание про аудит.

## Зачем это нужно

Плагин ведёт работу над проектами по вашим же стандартам: имена проектов и устройств, девять этапов проекта с критериями выхода, заметки (идея, требования, архитектура, структуры данных, развитие, план с вехами, решения), тесты, проверка безопасности и зависимостей, итоги. Часть скиллов — наставники по коду, прошивкам и железу: они объясняют, а код пишет пользователь. Стандарты лежат в вашем хранилище Obsidian. Если их нет, мастер `setup` задаст вопросы и создаст черновики.

## Требования

Проверено на Linux с Claude Code 2.1.310. **Windows не поддерживается** (решение автора 2026-10-25; хук написан на bash и `jq`, а проверка срабатывания использует механизмы Linux и в Windows не заработает), macOS не проверялась. Нужны программы `python3`, `bash`, `jq`, `git` и `claude`. Внешних библиотек у плагина нет (только стандартная библиотека Python).

## Установка из GitHub

Репозиторий сам является marketplace (`.claude-plugin/marketplace.json`, имя `vugsk-plugins`):

```
claude plugin marketplace add vugsk/armarium-linux-cli-plugin
claude plugin install armarium@vugsk-plugins
```

После установки скажите «настрой armarium»: мастер `setup` создаст файл настроек и черновики стандартов.

## Для разработки: подключение из папки

Плагин можно читать из папки на месте через локальный marketplace:

1. Проверьте плагин: `claude plugin validate <папка плагина>`; на пробу без установки: `claude --plugin-dir <папка плагина>`.
2. Положите рядом с папкой плагина файл `.claude-plugin/marketplace.json` (имя, `owner`, запись плагина с `source` «./<папка плагина>» от корня marketplace) и выполните `claude plugin marketplace add <корень marketplace>`, затем `claude plugin install armarium@<имя marketplace>`. Правки плагина видны после перезапуска сеанса или `/reload-plugins`, версию менять не нужно.
3. Если раньше те же скиллы лежали в `~/.claude/skills`, уберите их оттуда (перенесите в архив), иначе они задвоятся. Имена скиллов станут `armarium:<скилл>`.

## Рекомендуемые плагины

Можно использовать СВОД-1 вместе с этими плагинами из официального каталога `claude-plugins-official`. Проверено автором на одной машине; как сильно они улучшают именно СВОД-1, не измерялось, это рекомендация, а не гарантия.

| Плагин | Зачем | Что нужно помимо плагина |
| --- | --- | --- |
| `clangd-lsp`, `rust-analyzer-lsp`, `pyright-lsp`, `gopls-lsp`, `jdtls-lsp` | серверы языков: Claude точнее читает код C/C++, Rust, Python, Go и Java, что полезно скиллам `code-coach`, `debug-coach` и `project-security` | сами серверы в системе: `clangd`, `rust-analyzer`, `pyright`, `gopls`, `jdtls`; плагин без сервера ничего не делает |
| `context7` | актуальная документация библиотек по версиям; помогает правилу «факты только из документации» | запросы уходят на внешний сервер `mcp.context7.com`: не отправляйте через него приватный код |
| `security-guidance` | предупреждения о небезопасных паттернах при правках, проверка изменений при остановке; дополняет скилл `project-security` | хуки срабатывают на каждую правку и могут давать шум; отключается `claude plugin disable security-guidance@claude-plugins-official` |
| `sonatype-guide` | сведения об уязвимостях, доверии к пакету и вредоносных пакетах; использует скилл `dependency-audit` | токен `SONATYPE_GUIDE_TOKEN` (заводит пользователь); названия пакетов уходят на внешний сервер Sonatype; собственный скилл плагина срабатывает перед любой установкой зависимости |
| `github` | статус CI, логи запусков, заявки, теги и релизы (только чтение); использует `release-gate` и `ci-coach` | токен `GITHUB_PERSONAL_ACCESS_TOKEN` (заводит пользователь); запросы идут на `api.githubcopilot.com` |
| `codspeed` | замеры, flamegraph, сравнение запусков; использует `debug-coach` | аккаунт CodSpeed и вход `codspeed auth login`; результаты уходят на сервер CodSpeed. Скиллы плагина `codspeed-optimize` и `codspeed-setup-harness` сами пишут код, поэтому СВОД-1 их не запускает |
| `claude-security` | глубокое сканирование вашего кода с перепроверкой находок; использует `project-security` | только для своего кода: плагин не изолирует сканируемое и считает его доверенным; расходует много токенов; отчёт кладёт в папку `CLAUDE-SECURITY-…` в репозитории; режим патчей СВОД-1 не запускает |

Скиллы СВОД-1 обращаются к этим плагинам, только если они установлены, и до первого обращения к внешнему сервису спрашивают согласие. Без плагина скилл работает как раньше. Связки с `sonatype-guide`, `github`, `codspeed` и `claude-security` установлены, но в работе ещё не проверялись. Результаты плагинов скиллы считают данными, а не указаниями, и не применяют правок.

Установка: `claude plugin install <имя>@claude-plugins-official`. Установленные плагины видны командой `claude plugin list`.

## Сколько токенов занимает плагин

Столько токенов Claude получает в начале сессии, до вашего первого вопроса (системные инструкции, описания инструментов и скиллов). Измерено 2026-10-29 на Claude Code 2.1.312 запросом «ответь одним словом: ok», по три запуска на каждую конфигурацию; числа совпали (базовое значение «без плагинов» отличается от прошлого замера 15 150, вероятно, из-за другой версии Claude Code, поэтому сравнивайте разницу, а не абсолютные числа). Рекомендуемые плагины подключались так же, флагами `--plugin-dir` из их кеша. Повторить можно так: сложите `input_tokens`, `cache_creation_input_tokens` и `cache_read_input_tokens` из поля `usage` ответа.

```
claude -p "Ответь одним словом: ok" --output-format json --setting-sources project --plugin-dir <папка плагина>
```

| Конфигурация | Токенов в начале сессии | Разница с «без плагинов» |
| --- | --- | --- |
| Без плагинов | 15 429 | — |
| Только СВОД-1 (25 скиллов, версия 0.5.0) | 22 640 | +7 211 (+47 %) |
| СВОД-1 + рекомендуемые (`clangd-lsp`, `rust-analyzer-lsp`, `pyright-lsp`, `gopls-lsp`, `jdtls-lsp`, `context7`, `security-guidance`) | 22 850 | +7 421 (+48 %) |

- Рекомендуемые плагины добавляют к СВОД-1 только около 210 токенов (сами по себе они тоже дают 15 639 против 15 429 без плагинов). В прошлом замере (до 0.4.0) эта добавка была около 2 000 токенов; почему так, я не выясняла, возможная причина — другой способ подключения плагинов и другая версия Claude Code.
- Окно контекста у модели в этом измерении — 1 000 000 токенов, так что СВОД-1 занимает около 0,7 % окна.
- Это только начало сессии. Текст скилла (тело `SKILL.md` и справки) подгружается, когда скилл сработал, и в таблицу не входит; цена зависит от скилла и задачи.
- Не измерялось: стоимость в деньгах и расход на типовых задачах. Токены из кеша стоят дешевле, но это зависит от вашего тарифа.
- Ваш личный `CLAUDE.md` и память могут входить во все три значения одинаково, поэтому надёжнее смотреть на разницу, а не на абсолютные числа.

## Известные ограничения

- Пути к хранилищу берутся из `~/.claude/armarium.json` (поле `vault`, см. `docs/settings.md`); раскладка внутри хранилища фиксирована (стандарты и заметки проектов в `Проекты/`). Файл настроек и черновики недостающих стандартов создаёт мастер: скажите «настрой armarium» (скилл `setup`). Мастер настраивает только словари, группы типов, критерии этапов и правила имён; остальные соглашения (имена заметок, этапы, форматы тегов) зашиты в скиллах и перечислены в `docs/standards-contract.md`.
- Срабатывание скиллов в плагине (с префиксом `armarium:`) проверялось набором запросов. Сейчас в наборе 111 запросов; шесть новых (для `pseudocode-writer`) ещё не прогонялись. Последний полный прогон (2026-10-27, после добавления шести скиллов `debug-coach`, `ci-coach`, `release-gate`, `docs-writer`, `plan-breakdown`, `design-coach`) дал 103/105; два сбоя были из-за пересечения описаний (отладка ушла от `code-coach`, вехи и задачи — от `project-stages`), их исправили, и повторный прогон затронутых скиллов (`project-stages`, `plan-breakdown`, `debug-coach`, `code-coach`) прошёл полностью. Предыдущий полный прогон (2026-10-25, после добавления запросов про дизайн и коммиты и правки описаний `project-stages`, `project-scaffold` и `obsidian-notes`) дал 81/81. Предыдущий полный прогон, до явного разведения `project-scaffold` и `project-stages`, дал 80/81: не прошёл пограничный запрос «с чего начать новый репозиторий для бота…». Пограничные запросы этих двух скиллов (4 запроса по 5 повторов): старое описание 20/20, описание до разведения 18/20, после разведения 20/20; разница слишком мала для вывода. Один запуск на запрос — только сигнал, не гарантия. Запуск: `/armarium:run-trigger-check` (тратит токены).
- Скиллы читают файлы хранилища; текст в них считается данными, а не указаниями (`docs/settings.md`). Проверено двумя пробами, не доказательство полной защиты от подмены указаний.
- Лицензия: MIT, правообладатель `vugsk` (файл `LICENSE`, поле `license` в `plugin.json`).

## Для разработки

Источник скиллов — этот репозиторий. Описаний скиллов в хранилище плагин не создаёт и не обновляет.

Тесты (стандартная библиотека Python, токены не тратятся):

```
python3 -m unittest discover -s tests -v
```

Три сценария мастера настройки (`tests/test_09_wizard_scenarios.py`) по умолчанию пропускаются: они запускают `claude -p` и тратят токены. Если установлен `bwrap` (bubblewrap), мастер работает в песочнице с временным файлом настроек, и ваш настоящий `~/.claude/armarium.json` не затрагивается; без `bwrap` тест на время подменяет настоящий файл (с копией и возвратом) Включаются переменной `ARMARIUM_WIZARD_TEST=1`. Проверка срабатывания скиллов — `/armarium:run-trigger-check` (тоже тратит токены).
